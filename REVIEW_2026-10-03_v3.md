## 🟠 High

### H1 — PDF report export cannot render Bengali — exported PDFs are unreadable
- **File:** `app/reports/page.tsx:258` (`exportPdf`)
- **What's wrong:** `new jsPDF()` with default fonts (Latin-1 only) writes member names, dates, amounts via `doc.text()`. Every Bengali glyph renders as tofu/blank. CSV/Excel exports carry the same Bengali strings and work fine — only PDF is broken.
- **Why it matters:** Akash relies on exports for financial records; a "PDF" button that produces a garbled document is a broken feature, not a cosmetic issue.
- **Fix:** embed a Bengali-capable TTF into jsPDF (`doc.addFileToVFS` + `addFont`), or drop the PDF button until that's done. Localize the header (`Foundation Report - monthly - donations` → Bengali) while there.

## 🟡 Medium

### S-M1 — `enforce_member_self_update` trigger logic bypass lets members change their own pledge/status
- **Files:** `supabase/schema.sql:383-412` (live function), trigger `trg_member_self_update` (`schema.sql:637`)
- **What's wrong:** the first `IF` returns early (allowing the row) whenever *any* allowed field changed, so the protected-field check below never runs in that case:
  ```sql
  IF NEW.id IS DISTINCT FROM OLD.id OR NEW.name IS DISTINCT FROM OLD.name
     OR NEW.address IS DISTINCT FROM OLD.address OR NEW.phone IS DISTINCT FROM OLD.phone THEN
    RETURN NEW;   -- allows EVERYTHING, including protected fields
  END IF;
  IF NEW.monthly_pledge IS DISTINCT FROM OLD.monthly_pledge ... THEN RAISE EXCEPTION ...
  ```
  A member can run `UPDATE members SET address = address || ' ', monthly_pledge = 0 WHERE id = <own>` via the anon-key PostgREST endpoint and it passes. RLS `members_update_own` has **no column restrictions** (USING/WITH CHECK only pin `id`), so this trigger is the *only* guard — and it's bypassable. `docs/decisions/BUGS.md:457` documents the intent ("anyone else may only change name, address or phone"), so this is a genuine logic bug.
- **Why it matters:** a member can self-reduce `monthly_pledge` to 0 (future payments allocate as `unallocated`) or flip `status` to `'inactive'` to vanish from arrears/targets. UI (`app/profile/page.tsx:82`) only sends name/address/phone, so exploitation needs direct API calls — trivial in devtools for any authenticated member.
- **Fix (new migration):** check protected fields first and raise regardless of allowed-field changes:
  ```sql
  IF NEW.monthly_pledge IS DISTINCT FROM OLD.monthly_pledge
     OR NEW.status IS DISTINCT FROM OLD.status
     OR NEW.join_date IS DISTINCT FROM OLD.join_date
     OR NEW.created_at IS DISTINCT FROM OLD.created_at THEN
    RAISE EXCEPTION '...' USING ERRCODE='42501';
  END IF;
  RETURN NEW;
  ```
  Per repo convention this deserves a `BUG-###` entry in `docs/decisions/BUGS.md` before fixing.

### S-M2 — `admin_delete_user` breaks on FK constraints; can't delete any staff with history
- **Files:** `supabase/schema.sql:296-320`; route `app/api/admin/delete-user/route.ts:24`
- **What's wrong:** the RPC nulls `donations.created_by/collected_by` then `DELETE FROM auth.users`, but `member_pledge_history.created_by`, `payment_allocations.created_by`, `expenses.created_by`, `notices.created_by` all `REFERENCES auth.users(id)` with **no `ON DELETE` action** (`schema.sql:144-155`). Deleting any treasurer/admin who ever created a record → FK violation → whole statement rolls back → route returns 409 with a raw FK error.
- **Why it matters:** the "remove staff" control is functionally broken for real staff — an admin cannot cleanly revoke a compromised staff account. (`public.users` is fine — `users_id_fkey` has `ON DELETE CASCADE`. Last-admin case is safe: self-delete is blocked, so zero-admin is unreachable.)
- **Fix:** also `UPDATE ... SET created_by = NULL` on the four tables before the delete (or change the FKs to `ON DELETE SET NULL`). Deserves a `BUG-###` entry per repo convention.

### U-M1 — Latin digits leak on profile page (`.toLocaleString()` without locale)

### U-M3 — Color-contrast failures on small text (measured)
- `text-emerald-600` on white = **3.77:1** (needs 4.5:1). Used for small links/labels everywhere: dashboard "বিস্তারিত দেখুন"/"সব দেখুন" (`app/dashboard/page.tsx:178,227`), report table method cells; `.btn-emerald` white-on-emerald-600 is also 3.77:1 (14px bold doesn't qualify as large text).
- `text-gray-400` on white = **2.54:1**. Pervasive helper text: dashboard subtitles, table headers, form hints (dozens of pages).
- Gold `#C9A227` on paper `#FDFCF7` = **2.36:1**: receipt "দান রসিদ" eyebrow, 11px (`ReceiptPaper.tsx:88`) — illegible for low-vision users on the printed receipt.
- **Fix:** `emerald-700` (5.48:1) / `gray-500` (4.80:1) for small text; darker gold (e.g. `#7a5f14`, already used for the method badge at 5.49:1) for receipt microcopy. Decorative gold rules/✦ can stay.
