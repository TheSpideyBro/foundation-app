## 🔴 High

### H1 — `components/layout.tsx:99`: leftover `font-hind` defeats the whole "Akkas default font" rollout
- **File:** `components/layout.tsx:99`
  ```tsx
  <div className="min-h-screen bg-[#FDFCF9] flex flex-col lg:flex-row font-hind overflow-x-hidden">
  ```
- **What's wrong:** Commit `d8ffedc` changed `<body>` to `font-akkas` and fixed the receipt/verify/error/not-found wrappers, but missed the `AppLayout` root shell — the div every authenticated page renders inside. The explicit `font-hind` here overrides the inherited `font-akkas` from `<body>`, so **the entire logged-in app still renders in Hind Siliguri**. Only the 3 public pages that bypass the shell (`/`, `/login`, `/signup` — see `app/layout-wrapper.tsx:12-14`) actually get Abu J M Akkas.
- **Why it matters:** This was the rollout's headline change ("true default body font"); as shipped it is a no-op for every logged-in user, and body typography is now inconsistent between public and authenticated pages.
- **Fix:** `font-hind` → `font-akkas` on that div (one word).

### H2 — Legacy JPEG receipt prints garbage batch totals (`৳ 0500300/-`)
- **File:** `app/api/receipts/[id]/route.ts:88`
  ```ts
  displayAmount = batchDonations.reduce((sum: number, d: any) => sum + d.amount, 0);
  ```
- **What's wrong:** `donations.amount` is `numeric` (`supabase/schema.sql:40`), which PostgREST serializes as a JSON **string**. `0 + "500" + "300"` → `"0500300"` (string concatenation, not addition). Every legacy batch receipt therefore prints a wrong total *and* a wrong কথায় amount (`numberToWordsBengali(displayAmount)` at line 271 consumes the garbage string). Pre-existing (dates to `bae040e`), not branch-introduced, but absent from both baseline reports. The new HTML receipt already does this correctly (`Number(r.amount)` in `app/donations/[id]/receipt/page.tsx:154-156`).
- **Why it matters:** Wrong money on a printed financial document, reliably triggered on all multi-month batch receipts via the still-live Preview/Download buttons.
- **Fix:** `sum + Number(d.amount)` — port the new page's correct version back.

## 🟠 Medium

### M1 — `receipt_no` not URL-encoded in verify URLs (3 spots)
- **Files:** `app/donations/[id]/receipt/page.tsx:116` (`` `${window.location.origin}/verify/${donation.receipt_no}` ``), `app/api/receipts/[id]/route.ts:367`, `app/donations/page.tsx:58`.
- **What's wrong:** `receipt_no` is staff-entered/bulk-imported; validation (`app/api/payments/route.ts:212-213`) only bans `\r\n\t` and caps length at 64. A number containing `/`, `?`, `#`, or `%` produces a broken QR target (`/` adds path segments → 404; `#` truncates). Donor scans → dead link.
- **Fix:** `encodeURIComponent(donation.receipt_no)` when building the URL in all three places. (`app/verify/[receipt_no]/page.tsx` already trims; Next decodes path params.)

### M2 — Batch receipt's QR contradicts its printed total
- **File:** `app/donations/[id]/receipt/page.tsx:114-117` vs `:149-160`.
- **What's wrong:** When batch consolidation applies, the page prints the **summed batch amount** with a `"X (Batch)"` receipt number, but `verifyUrl` still encodes the **individual** `donation.receipt_no`. A donor scanning the printed QR lands on `/verify/<individual-no>` showing only that row's amount — contradicting the document they hold.
- **Fix:** Decide the semantics — make the verify page batch-aware (accept batch id / sum the batch), or don't present the batch total as *the* receipt amount on the QR-bearing document.

### M3 — `/api/qr` has no try/catch around `QRCode.toBuffer`
- **File:** `app/api/qr/route.ts:19-23`.
- **What's wrong:** Any throw (pathological input such as unpaired surrogates; text exceeding QR capacity after decoding) becomes an unhandled rejection → Next.js 500 with an HTML body and wrong Content-Type instead of a clean JSON error. Public endpoint, no guard.
- **Fix:** Wrap in try/catch; return 400/422 JSON on encoding failure.

### M4 — QR block causes a hydration mismatch (QR flickers in late)
- **File:** `app/donations/[id]/receipt/page.tsx:113-117` + `ReceiptPaper.tsx:148-160`.
- **What's wrong:** The page is a client component but still server-prerendered. Server render: `typeof window === "undefined"` → `verifyUrl = null` → signature-only markup. Client first render: `verifyUrl` is a string → QR markup included. Different trees → React hydration mismatch (dev error, production client re-render); the QR visibly pops in after load on every view.
- **Fix:** Compute the URL in `useEffect` into state (render QR only when mounted), or build the verify URL server-side and pass it down.

## 🟡 Low

### L1 — Dead font declarations: Sabbir Sorolota + Anek Bangla loaded but never used
- `app/layout.tsx:40` (`--font-anek`) and `:59` (`--font-sabbir`) have **zero** class usages anywhere (Sabbir was replaced on the masthead by Shadhinata; Anek by Nakkhatra). Their `@font-face` CSS ships on every page; browsers won't download unused families, but it's dead weight plus extra licensing surface for the Lipighor TTFs (~260KB Sabbir files).
- **Fix:** Remove the two `localFont`/Google declarations and `@theme` tokens if they're truly retired — or keep deliberately as design tokens (then document that).

### L2 — All 5 Italic TTFs are unused (~550KB)
- No `italic` + custom-font combination exists anywhere in `app/`; only the Regular files are ever referenced. The Italic `@font-face` rules (3 per family incl. fallbacks) ship unused.
- **Fix:** Drop the Italic entries from the `localFont` `src` arrays (or keep if italics are planned).

### L3 — Batch receipt-number display drops the number
- `app/donations/[id]/receipt/page.tsx:160` and legacy `route.ts:89`: `` `${(d.receipt_no || "").split("-")[0]} (Batch)` `` — `"FHF-2026-0001"` renders as `"FHF (Batch)"`; the number is lost. Consistent with legacy, but almost certainly meant `split("-").slice(0, -1).join("-")` or the full number + `" (Batch)"`.

### L4 — `monthLabelBengali(null)` throws on null batch `donation_month`
- `app/donations/[id]/receipt/page.tsx:151-152` casts `donation_month` as `string`, but the column is nullable; `lib/utils.ts:95` calls `ym.split("-")` with no null guard → TypeError → blank receipt. Legacy's `getBengaliMonthName` handles null safely.
- **Fix:** Coalesce/guard before calling (mirror the legacy null handling).

### L5 — Batch query has no `member_id` guard (defense in depth)
- `app/donations/[id]/receipt/page.tsx:143-148` (same in legacy): groups by `batch_id` only. `batch_id` is a uuid so cross-member collision is unlikely, but `.eq("member_id", d.member_id)` is a one-line guard against a corrupted/misassigned batch_id rolling another member's donations into the sum.

### L6 — Batch month count assumes one row per month
- `page.tsx:152-156` (and legacy): count = `batchRows.length`. Two rows covering the same month inflate the "(০৩ মাস)" label. Minor.

### L7 — Legacy QR prefers `NEXT_PUBLIC_SITE_URL` env over request origin; new receipt uses `window.location.origin`
- `app/api/receipts/[id]/route.ts:366` vs `app/donations/[id]/receipt/page.tsx:116`. If the env var is stale or points at a different host than production, old and new QRs target different hosts.
- **Fix:** Align legacy to `request.nextUrl.origin`, or verify the env var matches production.

### L8 — `/api/qr` is a public, CPU-bound endpoint with no rate limiting
- `app/api/qr/route.ts` + `middleware.ts:58` (matcher excludes `/api/*`). Public-by-design is fine and the 512-char cap bounds cost, but it's effectively an open free QR-generation service. Consider a light edge rate limit. (No SSRF — the text is only *encoded*, never fetched — that check passes.)

### L9 — New HTML receipt is staff-only; legacy JPEG let member-owners view their own
- `app/donations/[id]/receipt/page.tsx:119` vs legacy `route.ts:102` (`isStaff(...) || userData?.member_id === donation.member_id`). Not a vulnerability — RLS (`donations_select_own` / `donations_select_staff`) still enforces row access — but donors lose the ability to view/print their own receipts: a product parity regression unless staff-only is intentional.

### L10 — Hardcoded production URLs in two more spots
- `app/layout.tsx:144,160` — `metadataBase` / canonical hardcoded to `https://daulkharfoundation.vercel.app` (should follow `NEXT_PUBLIC_SITE_URL`).
- `app/api/members/[id]/qr/route.ts:26` — same hardcoded fallback (mitigated by the env var, but stale on a custom-domain move).

### L11 — `text-md` is a dead class (pre-existing)
- `components/layout.tsx:106` uses `text-md`, which is not a Tailwind size — zero CSS emitted (verified in built bundle), so the mobile header brand silently falls back to inherited size. Pre-existing, not from the font rollout.

### L12 — `@theme` fallback stacks are shadowed by next/font (informational, not a bug)
- Every `--font-*` is declared twice: `@theme` on `:root` (inside `@layer theme`, e.g. `"Li Shadhinata 2.0 Unicode", "Baloo Da 2", sans-serif`) and the next/font variable class on `<html>` (unlayered, e.g. `"shadhinata", "shadhinata Fallback"`). Unlayered beats layered, so next/font wins and the fonts render correctly (verified in built CSS). Consequence: the human-friendly fallbacks written in `globals.css` never apply — next/font's auto `"X Fallback"` does. If fallback behavior ever looks off, this dual declaration is the place to look.
